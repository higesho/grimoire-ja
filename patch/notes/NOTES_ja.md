# Grimoire 日本語化 調査メモ

対象: Grimoire: Heralds of the Winged Exemplar 3.0.0.0-R (Steam)

## 仕組み（確認済み）

- 書庫 `BUNDLE-Z.RSF`
  - 先頭 0xA2: ファイルサイズ、型の数、項目数、(8)、項目サイズ26、(6)、全データのバイト合計
  - 目次の各項目: 名前12バイト、flags、size、offset、データのバイト合計
  - 再構築は `tools/grimtool.py build`。何も変えなければ元のファイルと完全に一致する
- 暗号: exe の 0x6B5620 にある64文字の鍵4本でXOR（鍵は長さ % 4 で選ぶ）
- 文字描画: exe 内の画像ライブラリ（Fastgraph系）
  - 0x622E1C 描画（はみ出し処理なし）/ 0x623504 描画（はみ出し処理あり）/ 0x623490 幅 / 0x6230F8 高さ
  - フォントは96文字。ライブラリ自体は256文字のフォント（0x8000 フラグ）にも対応
  - ビットマップは「下の行から順」に格納する
- 日本語描画: `dll/grimjp.cpp`（代理 `version.dll`）
  - UTF-8 を含む文字列だけ、一時的な256文字フォントを作って元の関数で描く
  - 文字画像は GDI（MS ゴシック）でその場で生成
  - 設定は `grimjp.ini`（フォント名、サイズ補正、ログ）

## 問題点・方針が必要な点

1. **極小フォント（1番 BLOCK05、高さ5px）と 8px フォント** → 対応済み
   - 文字の高さが9px以下のフォントでは、美咲ゴシック（8×8ドット、`grimjp/misaki8.bin`）で描く
     - 変換: `tools/bdf2bin.py`、ライセンス: `dll/fonts/misaki_LICENSE.txt`（自由に使用・改変・再配布可）
   - RESISTANCES / CONDITIONS の一覧は行の間隔が5pxしかなく、日本語はどうしても重なる
     → 高さ6px以下のフォントで描くときだけ、DLL が `grimjp/tiny_fallback.txt`（訳文→英語）で英語に戻す
     → 対応表は `tools/make_fallback.py` が `MASTER.TXT` の `@CONDITIONS` と `@RESISTANCES` から自動生成
   - **注意**: ゲームはこれらの項目名を6バイトか9バイトで切り詰める（日本語では2〜3文字）。
     DLL は前方一致で探すので、この2つのセクションの訳語は「先頭2文字」と「先頭3文字」が
     互いに重ならないように訳すこと（`make_fallback.py` が重なりを警告する）
   - 人体図の部位名なども同じく2〜3文字で切れるので、短い訳語にすること
2. **exe に直接書かれた英語** → 対応済み（`dll/ui_strings.txt`、インストール先 `grimjp/ui_strings.txt`）
   - DLL が描画の直前に文字列を置き換える（exe 本体は書き換えない）
   - 書式: `英語<TAB>日本語`（完全一致）、`~パターン<TAB>訳`（`*`=任意、`#`=数字列）
   - 高さ6px以下の極小フォントでは置き換えない（英語のまま）
   - **ウィジェット用フォント**（設定画面の項目名など、色付きの飾り文字）は別の描画関数
     - 0x4E2220 描画 / 0x4DE450 幅（(文字数-1)×文字送り の等幅計算）
     - 日本語を含む場合は Fastgraph の描画関数で単色描画する。色は `grimjp.ini` の `widget_color_index`
       （画面は256色パレット。`TRUERGB.PAL` の番号。既定 49 = 明るい紫）
   - 収集モード: `grimjp.ini` の `collect_ascii=1` で、描画された英字だけの文字列を
     `grimjp/collected_ascii.txt` に記録できる（擬似訳の書庫と組み合わせると exe 由来の英語だけが残る）
   - exe 内の候補一覧: `exe_string_candidates.txt`（開発用ツールの文字列も含む）
   - 未確認: 店・自動販売機・宝箱・アイテム説明・呪文詠唱・パーティ作成の画面（表には登録済み）
3. **データベース内の英語** → 対応済み（`tools/dbtext.py`、`grimtool.py extract/build` に組み込み）
   - アイテム名・モンスター名・呪文名はテキスト表（`MASTER.TXT` など）にある。データベース側には無い
     （`SPL` の呪文名は台本内のコメントだけで、画面には出ない）
   - `GPC.DBS`（暗号化あり・サイズ固定）→ `extracted/DBS/GPC.DBS.txt`
     - 職業15種 × 称号9個（各12バイトまで＝日本語4文字）、職業の説明（80バイトまで＝日本語26文字）
     - 技能の説明53件（各80バイトまで）
     - 行の書式 `位置:最大バイト:詰め物<TAB>本文`。上限を超えると build がエラーで止まる
     - 称号の日本語表示はステータス画面で確認済み。技能・職業の説明の表示場所は未確認
   - `NPCWORDS.MLB`（**暗号化なし**・長さ可変）→ `extracted/DBS/NPCWORDS.MLB.txt`
     - NPC共通の会話知識。514件。訳すのは VERBOSE（長い答え）と BRIEF（短い答え）の355件、約4.4万文字
     - 行の書式 `番号.VERBOSE<TAB>本文`（改行は `\n`）。`# 番号 TAG=… SYNONYMS=…` は参考用のコメント行
     - SYNONYMS は**プレイヤーが入力する単語**なので英語のまま残す
     - 書き戻しは元データと完全一致を確認済み。会話画面での表示は未確認
   - 以前の取り出しは `NPCWORDS.MLB` を誤ってXORしていた（修正済み、`is_plain()`）

#7. **文字の掃除処理** → 対応済み
   - 0x4FBFC0 は「空白・記号・英数字のどれでもないバイト」を空白に置き換える。日本語が消えていた
   - CRT の判定関数: 0x630D94 isspace / 0x630E13 ispunct / 0x630E97 isalnum / 0x630B10 isalpha
   - 0x4FC05E の isspace 呼び出しを DLL の関数に差し替え、0x80 以上のバイトを残す
   - 0x4FBE40 は前後の空白を削る普通の Trim（触らない）。0x4FBD30 は大文字化（a〜z のみなので無害）
#9. **名前の途中で切れた日本語** → 対応済み（2026-11-06）
   - 症状: 戦闘の一覧で未鑑定の魔物名が `?ハチドãƒ?` と化けた
   - 原因: `grimtool.py` が長い行に折り返し用の空白（`jptext.softbreak`）を入れていた。
     魔物名の行（`名前,複数形,未鑑定名,未鑑定複数形,群れ`）は全体では長いので、名前の1文字ごとに空白が入り、
     「ハチドリ」が15バイトになっていた。ゲームは名前を `Left()` で切るので文字の途中で切れた
   - ゲームの切り詰め（0x5CC050 が魔物名を作る。`Left` = 0x4FBBC0 → `Mid` = 0x4FBAA0）
     - 鑑定済み 20バイト、未鑑定 14バイト（`?名前?` の中身）
     - モード0は魔物データの固定長の欄に strcpy される（0x5C6CFE, 0x5CBBA6）ので上限は変えない
     - モード1・2は一覧表示用の文字列だけに使われる
   - 対策
     1. `grimtool.encode_text` はカンマ区切りの行を欄ごとに softbreak する（短い名前には空白が入らない）
     2. DLL が `Mid` をフックし、切る位置を UTF-8 の文字の境目まで戻す（全ての `Left`/`Mid` に効く）
     3. DLL がモード1・2の上限を広げる: 鑑定済み 20→30、未鑑定 14→21 バイト（0x5CC26D, 0x5CC2B7, 0x5CC3EC）
   - 確認: 休息中の戦闘で `?ハチドリ?` と正しく表示（`screenshots/combat_names_fixed.png`）
   - モード0（魔物データ内の名前）は上限を変えられないので、長い魔物名は戦闘用の短い名前にした
     - 対応表 `glossary/monster_short.tsv`（長い訳 → 短い訳、52件）。`build_patch.py` が @MONSTERS の名前欄だけ差し替え、
       上限（名前20・複数形30・未鑑定14・未鑑定複数形21バイト）を超える欄があれば WARNING を出す
     - 用語集の訳（会話・説明文で使う長い名前）はそのまま。例: ヴァンガード兵 → 戦闘では「前衛兵」、イライアス・コナカー → 「イライアス」
     - 03628 以降の謎解きの行は英語でも上限を超えているので対象外
     - 短い名前は該当する魔物と戦っていないので、画面では未確認
   - 調査用の設定（`grimjp.ini` の `[debug]`）: `trace_mid=1`（Mid の呼び出しを記録）、
     `trace_broken=1`（壊れた UTF-8 を描いた時の呼び出し元を記録）、`toupper_probe=1`、`trace_tilde=1`（`~` の字形と群れの名前の並べ替えを記録）、`force_identified=1`
#10. **群れの名前と `~`** → 対応済み・画面で確認済み（2026-11-06）
   - 0x5CC050（モード2・鑑定済み・2体以上）は群れの名前を「群れの語 + 空白 + 複数形」と単純につなぐ（0x5CC377〜）。
     英語は `Troop ~` + ` ` + `Soldiers`
   - ゲームのフォント6番（メッセージ・戦闘一覧）では `~`（0x7E）が "of" を合わせた一文字の字形。だから英語は「Troop of Soldiers」と出る。
     フォント7・8・10の `~` は普通の波線（DLL の `[debug] trace_tilde=1` で各フォントの字形をログに出せる）
   - 日本語の群れの語は全部 `~の部隊` の形なので、そのままだと「ofの部隊 前衛兵」になる
   - 対策: DLL の `fix_group()` が描く直前に「`~`<日本語の群れの語> <名前>」を「<名前><群れの語>」に並べ替える
     （「~の部隊 前衛兵」→「前衛兵の部隊」。名前の後ろの「×3」などはそのまま残す）
   - 訳文の中で `~` を "of" の意味に使うのはやめた: シェラク~眷属 → シェラクの眷属、ウォーフェア~魔術師 → ウォーフェア
   - 確認: 戦闘の一覧に「光蛾の大群」と表示（`screenshots/combat_group_name.png`）。
     群れの名前は鑑定済みの敵が2体以上のときだけ出るので、確認には `[debug] force_identified=1`
     （0x5CC0C6 を書き換え、名前を作る処理だけ全部の敵を鑑定済み扱いにする。確認用。通常は 0）を使った
#11. **戦闘指示の「職」欄**: 職業名は頭文字1文字で出る。15職業の訳語は頭文字がすべて違うので区別できる（確認済み）
8. **exe 内の差し込み用文字列** → `dll/exe_strings.txt`（起動時にメモリ上で書き換え、元の領域に収まるものだけ）

## 配布（置くだけ方式、2026-11-06）

- 原作のファイル（Grimoire.exe、BUNDLE-Z.RSF）は一切書き換えない。配るのは `dist/Grimoire_JP.zip`（約1.8MB）
  - `version.dll`、`grimjp.ini`、`grimjp/`（jp_bundle.pat、美咲フォント、ui_strings、exe_strings、tiny_fallback）、説明書
- `grimjp/jp_bundle.pat`（`tools/make_dist.py`）: 原作の書庫から日本語版の書庫への差分。
  「原作の何バイト目から何バイトをコピー」の指示と、差し替える93項目（訳文・画像・DB）だけを持つ。原作のデータは入らない
  - 先頭に原作の書庫のサイズと CRC32、日本語版のサイズと CRC32
- DLL（`ensure_bundle()`）: ゲームが BUNDLE-Z.RSF を開く時（exe の CreateFileA/W の import を差し替え）に、
  初回だけ `grimjp/cache/BUNDLE-Z.RSF` を作り（約1秒）、以後はそちらを開かせる。
  `grimjp/cache/stamp.txt` に原作と .pat のサイズ・更新日時を記録し、変わったら作り直す
  - 原作の CRC32 が合わない（版違い）・.pat が壊れている → 置き換えず英語で起動し、警告を別スレッドで表示。
    この時は ui_strings の置き換えも止める（英語と日本語が混ざらないように）。確認済み
  - 警告をゲームのスレッドで出すと、全画面の裏に隠れてゲームが止まった（修正済み）
- 作り方: `python tools/package.py`（patch_jp から書庫を dist_work/ に作る → 差分 → ファイルを集めて zip）
- 開発用の `install_test.bat` も同じ置くだけ方式に変更（ゲームのフォルダの書庫は原作のまま）。
  外すのは `restore_original.bat`（cache も消える）
- 説明書の元: `dist_readme.txt`
- 権利者への確認用のまとめ: `python tools/make_vendor_pack.py` → `dist/Grimoire_JP_review.zip`
  （英語の説明 `vendor_README.md`、配布用 zip、日本語データ、英日対照表 `data/review/*.tsv`、ソース、資料、画面写真。
  原作から取り出しただけのデータ・元画像・書庫は入れない）

翻訳対象の総一覧は `TRANSLATION_TARGETS.md`。

## 翻訳の方針メモ（会話）
   - このゲームは、プレイヤーが英単語を入力してNPCに尋ねる方式（入力欄は日本語入力不可の見込み）
   - 設定の「キーワード強調」は、会話文中の英単語を強調する機能。日本語訳では効かなくなる
   - 訳文では、尋ねられる話題を「黒の魔導士（LICH）」のように英単語を添えて書くとよい
     （添える英単語は `NPCWORDS.MLB.txt` の SYNONYMS か、台本 `*.CS` の `OnSubject_XXX` を参照）
4. **NPC の会話キーワード**
   - 台本（`*.CS`、AngelScript）は `OnSubject_JOB` のように英単語の話題名で分岐する
   - 台本側の話題名は英語のまま残す必要がある
   - 画面に出る話題名は `NPCWORDS.MLB`（TAG / SYNONYMS / VERBOSE / BRIEF）か DLL の置き換えで日本語化する
5. **画像になっている文字**
   - メインメニューのボタン、`LOCATIONS` / `ENCOUNTERS` / `ITEMS`、`RESISTANCES` などの見出しは画像
   - 必要なら画像の差し替えが別途必要
6. **訳文の長さ**
   - 擬似訳（全角1文字＝英字2文字分の幅）でも、物語画面の右端が少し欠けた
   - 訳文は1行あたり全角17〜18文字程度を目安にし、改行位置も調整する
